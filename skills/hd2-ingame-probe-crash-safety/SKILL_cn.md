# hd2-ingame-probe-crash-safety

[English](https://github.com/Puipipi/HD2-Agent-Skills/blob/main/skills/hd2-ingame-probe-crash-safety/SKILL.md) / 简体中文

> **置信度：** 下面的崩溃类别与防护措施在本工作区**已验证**——两个探针版本真的把游戏终止了
> （两次都是 `0xC0000409` fail-fast），两次都由加载器日志、探针日志与崩溃转储共同定位了原因。
> 防护写法本身是**转述**自本工作区已经在跑的模组，文中按转述标注。

游戏内探针是实时引擎里的**客人**，不是在沙箱里跑的脚本。这里有一条边界最要紧：
**`pcall` 只挡 Lua 错误，别的什么都挡不住。** 越过这条边界的原生故障会终止进程，
顺手带走玩家这一局的进度。

## 何时使用

- 你正在给运行中的游戏加只读诊断或测量 addon。
- 怀疑某个探针造成了崩溃、卡死或掉帧。
- 探针在载时游戏以 `0xC0000409`（`STATUS_STACK_BUFFER_OVERRUN` / `__fastfail`）终止。
- 加载器日志停在 `mods/<你>/<探针>: loading`，没有对应的 `: loaded`。
- 探针加载正常但日志什么都没有，你分不清「没有可报的」和「什么都没读到」。

## 真实发生过的两个崩溃类别

| | 案例 A | 案例 B |
|---|---|---|
| 现象 | 玩家**在菜单里**时 fail-fast | **启动时** fail-fast |
| 加载器日志 | 完整走完，随后进程死掉 | 最后一行是 `: loading`，没有 `: loaded`，也没有 `Startup finished` |
| 原因 | 没有每帧存取**脚本临时内存区**，它一直增长到溢出 | 用**凭空猜的签名**调引擎 API（`in_session()` 没传参数） |
| 成本 | **不是**原因——实测单次调用 0.00 ms | — |

两类都可以避免，而且 `pcall` 一个都挡不住。

## 规则

### 1. 绝不凭空猜引擎 API 签名——从跑得起来的模组里抄

漏传参数会一路进到原生代码，把进程带走。本工作区每个跑通的模组都带着 session 参数调：

```lua
-- 从已经跑起来的模组里抄签名。不要猜。
local ok, session = pcall(sr.Network.game_session)
if not ok or session == nil then return false, 'no session' end
local checked, value = pcall(sr.GameSession.in_session, session)   -- 带上 session
if checked then return value == true, 'GameSession.in_session(session)' end
```

调任何不熟的接口之前，先在已装模组里搜它、把每一处调用点读完。
在猜来的签名外面套 `pcall` 一点用都没有。

### 2. 每帧存取脚本临时内存区

跑通的模组把它当**每帧纪律**，不是偶尔为之的礼貌。

```lua
local saved = sr.Script.temp_byte_count()
-- ...这里是引擎读取...
sr.Script.set_temp_byte_count(saved)
```

先检查 `sr.Script` 与两个成员都是函数，并把这一对包进 `pcall`。
这个内存区不会自动为你重置，只分配不还原的一帧就会让它增长。

### 3. 在放大调用次数之前先测调用成本

「调用越少越安全」不是有用的问题——**一次调用到底多贵**才是。先逐键记录
单位数与毫秒数跑几帧，再决定频率。本工作区实测一次引擎查询 **0.00 ms**，
所以那次崩溃与调用量毫无关系；错的是我假定它有关系。

无论如何都要给帧设上界：测每帧耗时，超出预算就把间隔翻倍退避，
连续几次超标就**永久停止采样**。会拖累游戏的探针，不值它采到的数据。

### 4. 启动期什么都不碰；不要用「对象存在」推断状态

- 加载后头 ~20 秒一次引擎调用都不发；那时游戏还在初始化。
- **存在不是证据。** 飞船上有一个**完全静止**的、带目标资源 id 的单位，于是「对象存在」
  让探针在玩家挑选战备时连采了 29 秒。要拿**只有真东西才有的属性**做闸门——对扔出去的
  战备球来说就是「它动了」；并且按**单位句柄**保存逐实例状态，因为身份串是资源哈希，
  被所有实例共用。
- session 检查回答的是「有没有 session」，不是「玩家在不在任务里」：本工作区实测它
  **在飞船上就为真**。别把它当任务闸门。

### 5. 任何状态都写一条状态行

日志一声不响，与探针坏了是分不清的。按固定间隔写一行，把你真正读到的数字写进去——
世界数、session 状态及其原因、单位数、temp 字节数、上一帧耗时——不管有没有「事件」发生。

### 6. 边跑边刷盘

探针最有价值的数据往往来自结束得很糟的那一次。只在干净退出时才写盘的缓冲输出，
恰好会在你最需要它的时候丢掉。

## 诊断「怀疑是探针造成的崩溃」

| 看哪里 | 它告诉你什么 |
|---|---|
| 加载器日志的**最后一行** | `: loading` 而没有 `: loaded`，说明死在你 addon 内部 |
| `Startup finished: N loaded, M failed` | 本次会话有吗？没有说明启动从未走完 |
| 崩溃转储及其异常流 | 异常码；`0xC0000409` 是 fail-fast，不是普通访问违规 |
| 探针日志的最后几行 | 你自己的哪一步跑过了 |
| GameGuard / `NxStorage_*.txt` 的 DirectStorage 错误 | **噪音**——每个会话都有 15–20 条，跑得好的会话也有 |

## 速查

| 规则 | 省事的做法 |
|---|---|
| API 签名 | 搜已装模组，把调用连同参数表一起抄下来 |
| 临时内存区 | 每帧外面套 `temp_byte_count()` / `set_temp_byte_count()` |
| 成本 | 记录每次调用的单位数与毫秒数再定频率；预算、退避、自停 |
| 启动期 | ~20 秒宽限期，不发引擎调用 |
| 状态 | 用「只有真目标才有的属性」做闸门；绝不用「存在」 |
| 可观测 | 每个间隔在任何状态都写一条状态行 |
| 耐久 | 日志边跑边刷 |

## 常见错误

| 错误说法 | 事实 |
|---|---|
| 「`pcall` 会挡住」 | 它只挡 Lua 错误。原生故障直接终止进程。 |
| 「调用少一点更安全」 | 轴搞错了。先测单次成本，再给帧设上界。 |
| 「对象存在就说明事件发生了」 | 飞船上就有个静止的同类物件。用行为做闸门。 |
| 「`in_session` 说明我在任务里」 | 本工作区实测它在飞船上就为真。得找任务专属信号。 |
| 「肯定是那些 GameGuard 报错」 | 每个会话都记 15–20 条，健康的会话照样有。 |
| 「先让它跑通，再加防护」 | 防护就是让它跑通的东西。这里有两个版本死在缺防护上。 |
