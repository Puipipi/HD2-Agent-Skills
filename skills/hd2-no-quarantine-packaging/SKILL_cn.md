# 打包 mod，使其辅助脚本不被查杀

[English](https://github.com/Puipipi/HD2-Agent-Skills/blob/main/skills/hd2-no-quarantine-packaging/SKILL.md) / 简体中文

> **置信度:** 该机制是从 SmoothBoot 的源码读出来的，并未复现。拒绝含脚本归档的那个构建闸门*确实*在本地验证过。

一个需要用户运行*某个东西*的 mod —— 日志收集器、配置选择器、排除项工具 —— 有一个打包
问题：**mod 站点会查杀包含脚本文件的归档**，而一次被查杀的发布，在作者看来就是一封莫名其
妙的拒信，或者一个“上传成功”却没人能安装的 mod。

SmoothBoot 的解决办法是根本不随包交付脚本。本技能讲的就是这个模式。

## 规则

> 归档中**不含 `.bat`，也不含 `.ps1`**。mod 在首次运行时把辅助工具写进用户自己的配置目录，
> 随包交付的游戏内 README 会告诉用户它在哪里。

两半都重要：不含脚本的归档能通过扫描，而出现在可预测的本地文件夹里的辅助工具仍然可被
发现。用户体验不变；上传是干净的。

## 为什么运行时生成能过，而随包交付不能过

| 随 ZIP 交付 | 在用户磁盘上生成 |
|---|---|
| 扫描器可以在任何人运行它之前解开并检查它 —— 站点扫描干的正是这件事 | 扫描时这个文件还不存在 |
| 来自下载的未知 `.bat` 是经典的恶意软件形态 | 它由一个用户已经选择去运行的程序创建 |
| 它是你上传的产物的一部分，所以一次误报就会挡住发布 | 它是本地产物，就像一个配置文件 |

这不是对扫描器的规避：生成的文件是**平实、可读、没有任何混淆的 PowerShell**，mod 也在自己
的 notices 文件里这么说明。它避开的是*下载形态*的误报，而不是检测。

## SmoothBoot 是怎么做的

在 `mods/smoothboot/work/standalone/smoothboot.lua` 中：

```lua
local dir = HOME .. 'SmoothBoot/'          -- %LOCALAPPDATA%\CowboyBingus\Helldivers2\SmoothBoot\
local function wr(n, c)
    local f = io.open(dir .. n, 'w')
    if not f then error('cannot open ' .. dir .. n) end
    f:write(c); f:close()
end
...
wr('README.txt', readme)                   -- 指南，从源码中提取
wr('Collect-Logs.bat', [===[@echo off
rem Generated by HD2 SmoothBoot; run with the game closed.
chcp 65001 >nul
setlocal
tasklist /FI "IMAGENAME eq helldivers2.exe" 2>nul | find /I "helldivers2.exe" >nul
if not errorlevel 1 (
  echo Close the game first / Please close Helldivers 2.
  pause
  exit /b 1
)
powershell -NoProfile -Command "..."
]===])
```

值得照抄的细节：

- **朴素的 Lua `io.open(path, 'w')` + `EnsureDirectory`** —— 不 spawn 任何 shell 来创建文件
  或文件夹。（在本工作区，从更新线程里 spawn shell 曾把游戏挂死；见失败目录。）
- **只生成一次，带守卫，并重试有界的次数**，而不是每帧都做：调用方跟踪 `tool_attempts`，
  几次尝试之后就停下。
- **生成的批处理是防御性的**：它检查游戏是否仍在运行，并以清晰的消息拒绝执行；它设置
  `chcp 65001` 让自身的输出可读；它使用 `-NoProfile`，这样用户的 PowerShell profile 无法
  改变行为。
- **README 以同样的方式、从源码生成**，而归档内随包交付的 `README.txt` 也是从同一个源码
  字符串里提取的。单一事实来源，这样游戏内指南不会与代码漂移。
- **归档自己的构建脚本会强制这一点**，并把原因写在代码里：
  ```python
  # 归档里不放散落的 .bat（Nexus 会查杀脚本文件）—— 配套工具在
  # 运行时生成到 config.txt 旁边。
  ```
- **notices 文件会解释这件事**，这样评审者或用户能明白，为什么一个“用 .bat 收集日志”的
  mod 里却没有 .bat。

## 让它可被发现

生成文件只是事情的一半 —— 用户还得能找到它：

- 在 mod 的游戏内 README 和发布页面上写出确切路径
  （`%LOCALAPPDATA%\CowboyBingus\Helldivers2\<Mod>\Collect-Logs.bat`）。
- 说明它是在**首次运行之后**出现的，而不是安装时。
- 写入时就以那个级别把这件事记进日志：
  `companion tools ready: <HOME>SmoothBoot/Collect-Logs.bat`。

## 当你确实想随包交付脚本时

有时候辅助工具本身就是重点（独立的补丁器、安装器）。那么：

- 把它作为独立发布交付，而不是放在 mod 归档里，这样一次查杀不能连累 mod 一起下架。
- 直白地说明它做什么、以及它没有混淆，并把源码留在仓库里。
- 要有心理准备：第一次自动扫描有时仍会误报；规划一条人工复核的路径，而不是反复重传碰运气。

## 让生成器保持诚实

辅助工具的*事实来源*是 mod 源码，而不是你磁盘上一个散落的文件 —— 否则生成出来的副本和你
测试的版本会分叉。SmoothBoot 为此带了一个小工具：

```python
"""Replace the embedded, readable collector. No BAT is shipped in the ZIP."""
# work/tools/update_smooth_collector.py —— 重写 mod 源码中内嵌的那个字符串
```

通过那个工具（或者你自己直接改源码字符串）来编辑辅助工具，绝不要通过编辑 `%LOCALAPPDATA%`
里生成出来的文件来改 —— 那份副本会在下一次运行时被覆盖。

## 上传之前先验证

- 解开你的发布包，确认里面**没有 `.bat` / `.ps1` / `.cmd` / `.exe`**：
  ```powershell
  python -c "import zipfile,sys; z=zipfile.ZipFile(sys.argv[1]);
  bad=[i.filename for i in z.infolist() if i.filename.lower().endswith(('.bat','.cmd','.ps1','.exe','.vbs'))];
  print('script-like entries:', bad or 'none')" Your-Mod.zip
  ```
- 运行一次游戏，然后检查辅助工具确实被创建在 README 所说的位置。
- 把这项解包检查留在你的构建闸门里，这样以后的改动无法悄悄把它加回来。

## 这解决不了什么

- 它不能让一个真正恶意、或确实会被检出的文件通过。如果 *mod* 本身被标记，生成出来的辅助
  工具就无关紧要了。
- 它帮不上因为别的原因被标记的归档（捆绑的第三方二进制文件、未签名的可执行文件、与已知
  样本的校验和冲突）。
- 用户自己的杀毒软件在双击生成的 `.bat` 时，仍可能在他们机器上把它标记出来。要事先说明它
  做的每件事都是可读的，并让它尽量短。
