# HD2 事件聊天自动化

[English](https://github.com/Puipipi/HD2-Agent-Skills/blob/main/skills/hd2-event-chat-automation/SKILL.md) / 简体中文

本技能说明游戏事件已经识别之后的消息处理路径。事件识别是另一个问题；不能只凭提醒文本或规则名推断触发条件。上游证据和规范化事件见 [HD2 游戏事件识别](../hd2-game-event-identification/SKILL_cn.md)。以下 AutoChat 行为依据[玩家模板文档](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PLAYER-TEMPLATES.md)、[插件 API 文档](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PLUGIN-API.md)及其链接的源码和测试核实。它们是 AutoChat 的产品契约，不是所有模组都必须遵循的规则。

## 事件、欢迎和定时消息

AutoChat 的默认事件冷却桶按触发玩家共享，普通事件规则共用该桶。规则显式设置冷却后，该规则改用此玩家专属的独立桶，替代默认桶而不是叠加。被冷却拒绝的事件会被消费并标记为已见，不会留待桶重新开放后发送。这与已被接受、进入 AutoChat 有限内部 ping 队列的事件不同：暂时性发送失败时，已接受条目可在过期前重试。零冷却规则走紧急队列路径，但仍遵守总开关、去重、会话、角色、创建者和发送检查。欢迎消息按每位新加入玩家分别处理，仍遵守配置的延迟和每个会话一次的限制，但不会因事件冷却而延后。定时消息到期时也不受事件冷却影响，并保持自己的重复周期；欢迎和定时发送都不会刷新事件冷却记录。不要改成共享的全局丢弃门槛，否则同时加入的玩家可能无法各自收到欢迎。

## 身份、模板和输出

AutoChat 通过本地聊天发送，因此在当前实现中，显示发送者仍是本机玩家。`creator_id` 用于触发归属和筛选，不负责选择或伪造网络发送者。这项针对产品的事实不代表所有游戏引擎或模组都无法更改身份。

模板变量是格式化器替换的固定别名，不是正则表达式。玩家别名包括 `{player}`、`{player_name}`、`{name}`、`{short}`、`{abbr}`、`{slot}` 和 `{number}`；事件和任务别名包括 `{category}`、`{target}`、`{stratagem}`、`{action}`、`{objective}`、`{task}`、`{objective_type}`、`{task_type}` 和 `{position}`。欢迎、定时和插件消息可以使用玩家变量；事件变量仅在对应事件或任务上下文提供值时才有内容。变量只替换一遍：玩家名里的花括号或百分号会原样插入，不会再解释成第二个模板变量；未知变量保持原文。完整变量表和示例见上方模板文档。

AutoChat 核心提醒会把已知的完整玩家名整体包成一次 `[名字]`；身份缺失时使用不带方括号的队友回退文本。变量替换前，格式化器会移除名称中的控制字符和字面 `<`、`>` 分隔符；类似标签内部的文字会作为普通名称文本保留，因此不能保留玩家名自带的标记语法。单次替换后，花括号和百分号仍按字面处理。只有开启 `ping_sender_color` 时，核心才会给玩家名和标记前缀着色。插件消息会添加方括号，但不会自动着色。正文前会自动添加一个换行符。正文预算为 511 字节且包含颜色标记，因此开头换行符加正文必须不超过聊天的 512 字节限制。截断时既要保持 UTF-8 字符完整，也要在该预算内闭合活动颜色标记。主机输出默认是小队聊天，客机默认仅本地可见，但实际发送渠道由所选角色配置的 `output` 决定。本地输出失败时不会回退到公开聊天。

## 角色预设和保存状态

主机和客机使用独立预设池。中英双语的四个内置预设不可变：不能删除、覆盖或重命名。内置默认配置会开启实际提醒开关，同时保留角色输出默认值和单人权限策略；这不等于开启所有布尔值。事件规则覆盖列表初始为空，因此新预设不会生成零冷却规则。已退休的 `quick_timer_*` 字段不会写入可移植快照；加载预设时不得将其恢复成仍可用功能。新安装默认选中英文内置预设，且与 UI 语言无关。仅更换 UI 语言或选中预设不会应用预设设置，只有用户明确手动应用才会改变当前配置。不得把这些内置默认值迁移到用户已有设置或自定义预设。

可移植预设快照保存角色选项、可移植任务定义，以及明确选择接入预设钩子的插件数据。任务定义包含名称、模式、时间、消息和启用状态，不包含运行时 ID、到期时间、发送结果或进度。旧快照没有任务数据时，目标角色已有任务会保留。预设库没有常规的固定条目数量上限，但仍受载荷大小、持久化文件大小和序列号范围约束；应描述为受存储边界限制，而不是无限。

## 插件集成和批量编辑

AutoChat 插件契约说明了同级菜单注册、插件先于或后于 AutoChat 加载时的处理、游戏/API 语言来源、只读设置快照，以及可选的继承或独立发送策略。面板的英文预览语言只影响 UI，不应泄漏到插件语言或消息模板语言。插件独立设置冷却或输出方式时，仍须遵守会话、角色、创建者/归属、原生发送和消息合法性检查。插件发送 API 不排队也不做事件去重：独立策略使用 `cooldown=0` 时，每次有效调用都可能再次发送；需要时由调用方对重复事件回调去重。这与 AutoChat 核心事件管线自己的已见事件机制不同。调用方收到可重试失败时自行决定重试。预设集成通过四个可选钩子接入；应用前先预检，保留未知插件数据，并在应用失败时回滚。只读设置快照不得暴露可修改的主机状态。

AutoChat 的战备规则批量编辑属于内部 UI/后端功能：按角色和当前筛选范围处理，支持跨页并原子应用，同时保留无关规则字段。不要把它描述为公开插件 SDK 方法。
