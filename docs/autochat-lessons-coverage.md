# AutoChat lessons: coverage and evidence

English / [简体中文](https://github.com/Puipipi/HD2-Agent-Skills/blob/main/docs/autochat-lessons-coverage_cn.md)

This is an evidence index for reusable lessons extracted from the AutoChat work. It is not a product changelog or a claim that every behavior was tested in a live game. Product references below are pinned to immutable commit [`4445596a76ed387edc3c09d0d25aa9d06ffd5b11`](https://github.com/Puipipi/HD2-AutoChat/tree/4445596a76ed387edc3c09d0d25aa9d06ffd5b11). Read the linked skill for procedures; this page records what the AutoChat evidence does and does not establish.

Confidence labels: **offline** means a test ran against LuaJIT/fake engine boundaries; **source/build-pinned** means code or a native predicate was inspected for that revision; **target capture** means one narrow live observation. None implies complete coverage of other game builds.

## B. Event chat, templates, presets, and plugins

| ID | Reusable lesson | Skill and AutoChat evidence | Confidence and boundary |
|---|---|---|---|
| B1 | Core event cooldown buckets are per actor by default; an explicit rule cooldown uses that actor+rule bucket instead of stacking with the default. Cooling events are consumed/dropped, not held for later; accepted transient send failures retain their existing bounded retry behavior. A zero-cooldown core rule still uses the urgent path and its normal guards. | [Event chat automation](../skills/hd2-event-chat-automation/SKILL.md); [cooldown implementation](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/src/chat_automation.lua), [cooldown tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_chat_automation.py). | Offline policy/queue tests and pinned source. |
| B2 | Welcome timing is independent per newcomer; scheduled messages run when due despite event cooldown. Neither path writes or extends the event cooldown ledger. Their delay/recurrence, session, role, enable, solo/output, and native-send checks remain applicable. | [Event chat automation](../skills/hd2-event-chat-automation/SKILL.md); [welcome/scheduler tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_chat_automation.py), [scheduled tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_scheduled_tasks.py). | Offline timing/policy tests; no live multiplayer timing claim. |
| B3 | The local AutoChat core sends as the local player; `creator_id` is trigger ownership/filter context, not a network sender override. Do not generalize this implementation fact into an engine-wide impossibility claim. | [Event chat automation](../skills/hd2-event-chat-automation/SKILL.md); [output tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_role_output.py). | Product-source behavior and offline tests only. |
| B4 | Template tokens are fixed aliases, replaced once rather than interpreted as regular expressions. Names containing `%` or braces remain literal after replacement; unknown tokens remain. Sanitization removes controls and literal angle delimiters, not arbitrary tag-shaped contents. | [Player template guide](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PLAYER-TEMPLATES.md); [formatter tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_chat_automation.py). | Offline formatter tests and source. |
| B5 | The core formats a known full player name in brackets and colors only under its configured sender-color option; plugin messages get bracket formatting but no automatic name color. Missing identity does not gain fabricated brackets. | [Player template guide](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PLAYER-TEMPLATES.md); [formatter/output tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_chat_automation.py). | Offline formatter tests; rendering varies by configured output. |
| B6 | Message formatting starts the body with one LF; its 511-byte body budget includes color markup and must fit the 512-byte chat limit. Truncate at a valid UTF-8 boundary and close active color markup within budget. | [Player template guide](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PLAYER-TEMPLATES.md); [byte-budget tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_chat_automation.py). | Offline byte-level formatter tests; not a claim about every external chat transport. |
| B7 | Built-in presets are four role/language seeds and cannot be deleted, overwritten, or renamed. Their reminder flags are enabled while role output/solo policy is retained; this is not “all booleans on.” New-install English selection is separate from UI locale, and only manual apply changes active settings. Existing user settings/custom presets are not migrated. | [Plugin API/preset docs](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PLUGIN-API.md); [preset library tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_preset_library.py), [profile tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_auto_chat_probe.py). | Offline preset/config tests and source. |
| B8 | Plugin APIs are independent contracts: `cooldown=0` does not deduplicate repeated `send` calls, so callers must deduplicate callbacks; plugin calls do not inherit core queue/seen semantics. Independent policy still keeps legality/session/role/native-send checks. Preset hooks are opt-in, preserve unknown blobs, and should preflight/rollback. Readonly snapshots contain role options, portable task definitions (name/mode/time/message/enabled, not runtime IDs/due/results/progress), and opted-in plugin blobs; old snapshots without tasks leave destination tasks intact. No ordinary item-count cap, but payload (1 MiB), persistence (16 MiB), and safe-serial-number bounds apply. | [Plugin API](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PLUGIN-API.md); [plugin tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_plugin_integration.py), [snapshot tests](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/tests/test_preset_library.py). | Offline contract tests; plugin caller behavior remains the caller's responsibility. |

## Performance evidence and limits

The offline benchmark and its method are documented in [PERFORMANCE-OFFLINE-1.0.0.md](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/docs/PERFORMANCE-OFFLINE-1.0.0.md) and [`bench_frame_performance.py`](https://github.com/Puipipi/HD2-AutoChat/blob/4445596a76ed387edc3c09d0d25aa9d06ffd5b11/work/standalone/bench_frame_performance.py). For 1,000 active-role, enabled, unfinished tasks with future deadlines, the measured offline mean changed from 0.02250 ms to 0.00428 ms and periodic-poll mean from 0.60509 ms to 0.07849 ms. This is a LuaJIT/fake-engine comparison, not a guarantee of 0.05 ms per real game frame. The benchmark uses Lua-side QPC timing, fresh runtimes and warmup, fixed source references, Lua-table samples, and a counter-only GUI stub; report steady and periodic costs separately. A wrapped-text call-count reduction was withdrawn because it did not produce stable timing gains. Short default redraw hints do not represent long CJK/English text or large rule sets; measure a fixture that proves a real redraw, and keep layout correctness tests separate from timing.

## Reproduction and source boundary

The linked product source and tests are immutable evidence for the named revision. They are not a live deployment check. Before applying a fix to another setup, verify the active manager payload/resource hash and its separate patch build ID; the product version can remain `1.0.0` across patch builds. AutoChat's documented in-game IME acceptance is still pending. No result here establishes complete event-producer coverage, all-resolution native rendering, or successful live ship-to-mission GUI teardown.
