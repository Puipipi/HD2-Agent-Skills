# 验证状态

[English](https://github.com/Puipipi/HD2-Agent-Skills/blob/main/docs/verification-status.md) / 简体中文

本仓库**真正跑过或量过**什么,以及什么没跑过。这些 skill 的置信度并不一致,所以逐条写明,而不是靠行文的
语气去暗示。

这份文件存在的意义是执行两条规则:

1. **只有在本仓库跑过或量过的结论才算 "verified"(已验证)**,而且条目里要写明是怎么验的。在别人的
   文档里、或在某个已发布模组的源码里读到,都只是 **reported(据来源报告)**。
2. **reported 不是"另一种错",它只是"在这里没测过"。** 有几个 skill 是对某位贡献者笔记的重组,而那位
   贡献者明确说:并非所有内容都测试过,有些还需要别人来测。这些被标出来,正是为了让下一个人知道从哪
   开始。

## 使用的三个等级

| 等级 | 含义 |
|---|---|
| **verified 已验证** | 在本仓库执行过或测量过,且条目写明了是哪个命令、哪个文件或哪次测量做到的 |
| **reported 据来源报告** | 忠实复现自某个来源,本仓库未测试。来源自己可能测过,也可能没测过。 |
| **build-bound 受版本约束** | 只对某一个游戏 build、模组版本或日期成立,不可移植,请重新推导。 |

## 这对贡献者意味着什么

如果你要接手:**reported** 那些行就是你的测试最值钱的地方,上面大致按"需要运行中的游戏(最难、最有价值)"
到"只需要一个夹具(最容易上手)"排列。

- 最便宜的第一步:拿 `hd2-offline-engine-harness` 和 `hd2-addon-package-inspector` 对你的模组跑一遍 ——
  它们不需要游戏。
- 价值最高:凡是 `hd2-injection-runtime-patching` 与 `hd2-offline-data-workflow` 里的东西,因为那两块
  完全建立在一个人(和一位贡献者)的笔记之上,只有实机才能确认。
- 你测出结果时,请写明**游戏 build 与模组版本** —— 这里若干事实是受版本约束的,而一个不带 build 号的
  确认,用处要小得多。
